# 应用配方

以下配方为本 Skill 新编写，不是原文案例，也不是对用户过往经历或成果的陈述。它们结合此前中文精读中的应用方向。使用时以本次任务实际提供的资料为准。

## 作品集与交互设计

**用户可能的请求：** 帮我把作品集做得更有说服力，而不只是好看。

先读取真实项目资料、招聘目标与现有作品集。把目标落在读者是否能理解问题、设计决策和证据，不擅自替用户决定项目或投递方向。

建立“主张—证据—展示位置”对应关系。区分真实研究、设计者推断、原型功能、已实现功能和未来计划。缺少测试资料时保留缺口，不能补造参与人数、转化率或访谈引语。

使用信息架构和编辑方法安排阅读路径；使用交互设计方法处理导航与反馈；需要动效时先保证入口可发现与内容可读。不要以动画数量替代展示质量。

可交付：实际页面、案例结构或用户要求的文件。可检验：链接是否可用、信息是否对得上材料、关键路径能否操作、排版是否完整。若没有招聘者或真实用户反馈，不声称已验证招聘效果。

## 简历与实习材料

**用户可能的请求：** 针对这份岗位描述修改我的简历。

读取岗位描述和真实简历，按岗位需要对应职责、工具和证据。岗位页面可能变化时核对当前页面，不假定职位仍开放。

使用已有事实改善表达，保留贡献范围和完成状态。团队成果不得变成个人独立完成；计划不得变成落地；熟悉某工具不等于实际在项目中使用过。

沿用用户明确要求的语言、联系方式、版式和颜色。只做内容编辑时，不擅改代码、链接和标题。事实不足以支持某项岗位要求时，列在正文外作为资料缺口或能力差距。

可交付：可投递文件及必要的事实疑点。可检验：所有新增陈述能回到原始材料，时间与职责一致，文件能打开且文字未被裁切。更贴合岗位不等于保证获得面试。

## 公司与行业研究

**用户可能的请求：** 帮我研究一家公司，说明商业模式和主要风险。

先识别研究问题，不自动变成买卖建议。涉及当前价格、财报、管理层职位、订单或政策时搜索最新第一手来源，注明时间与口径。

分开企业披露、管理层主张、已计算的数据和分析推断。估值或财务计算显示公式、输入、单位和假设；不能把企业收入与股价混为一谈。

可采用财务核对、产品竞争、客户结构与反方检查，但每一种都必须贡献可核查的结果。竞争性解释应检验证据，不为平衡而编造负面材料。

可交付：有出处的研究、待核实问题和情景分析。可检验：关键数字与原始披露一致，比较口径一致，计算能复算。不得承诺收益，不将未经验证的预测写成事实，也不自动下单。

## 原型、3D 与工具型项目

**用户可能的请求：** 帮我把这个原型或场景做到能展示。

先检查是否真实拿到了文件、软件环境和操作权限。只有截图时，不能声称打开了模型或连接了本机软件。

确认需要的是效果图、交互演示、模型文件还是可生产结构。保留原设计不可更改的特征；结构改动与光影、材质、版式改动分别处理。

可跨用造型、视觉叙事和可用性方法，但不在没有测量、模拟或实体测试时声称强度、尺寸配合或安全性已验证。

可交付：实际修改过的文件或用户要求的导出物。可检验：文件可读、版本支持、关键部件和镜头没有遗漏、渲染结果可见。无法运行目标软件时明确说尚未在该软件验证。

## 从零学习与新方向探索

**用户可能的请求：** 我没有基础，怎么开始做这个方向的项目？

把宽泛兴趣缩成一个用户认可的可观察任务。先检查基础，而不是默认其已有编程、研究或行业经验。对不喜欢的工作方式可以比较替代路径，不承诺工具能消除所有学习成本。

第一轮交付一个能做的练习、最小原型或短测验。根据实际表现调整难度，不凭“看完了资料”判断已掌握。示例可为虚构练习，但必须明确标明。

需要尝试陌生工具时，检查官方资料和当前入口，核对免费、付费及权限条件。不得代购课程、订阅或提交个人资料。

可检验：用户是否能独立完成目标动作、解释关键限制，或复现一个结果。学习计划本身不等于能力已经提升。

## 严格润色与单步请求

**用户可能的请求：** 只把下面这段话写通顺，不增删信息。

直接编辑原文，保护独立信息与所有限定。不要重新定义作者想实现的目标，不加入营销主张，不展开跨领域分析，不附任务诊断。

完成后逐项比对：是否新增事实、丢失否定、增强确定性、改变施事者、混淆计划和完成、改变标题或受保护内容。最终只交用户要求的文本。

这是本 Skill 正常工作的一种方式，不是使用失败。
